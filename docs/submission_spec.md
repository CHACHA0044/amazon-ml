# Official Submission Specification — Amazon ML Challenge 2026

**Challenge:** Business Entity Resolution Challenge (Amazon ML Challenge 2026)  
**Evaluation Portal:** Unstop  
**Scoring Metric:** Official Macro-Averaged $F_{0.5}$ over Source-1 entities  

---

## 1. Official Submission Contract Overview

The competition requires two submission components:

1. **Leaderboard File (`matching_results.tsv`):** Uploaded via the Unstop web interface under *"Upload Matching Results File"*.
2. **Code Package (`.zip`):** Uploaded via the Unstop web interface under *"Upload Code File"*, containing reproducible code, blocking candidate audit, and documentation.

---

## 2. File Specifications

### 2.1 Final Matching Results (`matching_results.tsv`)
*This is the only file scored on the live leaderboard.*

- **Filename:** `matching_results.tsv`
- **File Format:** Tab-Separated Values (`.tsv`)
- **Encoding:** `UTF-8`
- **Delimiter:** Exact tab character (`\t`)
- **Header:** Exact lowercase tab-separated string:
  ```tsv
  source1_entity_id	matched_entity_ids
  ```
- **Row Semantics:**
  - Exactly **one row** for every Source-1 entity in `test_source1.tsv` (1,732,544 rows total, plus 1 header line = 1,732,545 lines).
  - Column 1 (`source1_entity_id`): The exact `S1-` entity identifier (e.g. `S1-00001`).
  - Column 2 (`matched_entity_ids`): Comma-separated list of matched `S2-` and/or `S3-` entity IDs (e.g. `S2-00047,S3-00812`).
  - **Singletons (Unmatched Entities):** When an S1 entity has no matched records, `matched_entity_ids` **must be left empty** (i.e. line contains `S1-xxxxx\t\n`).
- **Constraints & Validation Rules:**
  - **No duplicate rows:** Each `source1_entity_id` must appear exactly once.
  - **No duplicate IDs in match list:** E.g., `S2-001,S2-001` is strictly invalid.
  - **No Source-1 self-matches:** `matched_entity_ids` must NEVER contain any `S1-` IDs.
  - **Valid ID prefixes only:** Every ID in `matched_entity_ids` must start with `S2-` or `S3-`.
  - **ID existence:** All referenced IDs must exist in `test_source2.tsv` or `test_source3.tsv`.
  - **No trailing index column or quotes:** Pure unquoted tab-separated text.

### 2.2 Candidate Pairs (`candidate_pairs.tsv`)
*Audit file included in the final submission zip to verify blocking quality.*

- **Filename:** `output/candidate_pairs.tsv`
- **File Format:** Tab-Separated Values (`.tsv`)
- **Encoding:** `UTF-8`
- **Delimiter:** Tab character (`\t`)
- **Header:** Exact lowercase tab-separated string:
  ```tsv
  source1_entity_id	candidate_entity_ids
  ```
- **Semantics:**
  - Exactly one row per test Source-1 entity.
  - `candidate_entity_ids`: Comma-separated list of candidate `S2-`/`S3-` IDs generated by blocking before scoring.
  - All matched IDs in `matching_results.tsv` should be a subset of candidate IDs in `candidate_pairs.tsv`.

## 3. Code Package ZIP Structure

The final zip file (`<team_name>_submission.zip` or `amazon_ml_submission.zip`) must follow the exact official directory layout:

```text
amazon_ml_submission.zip
├── output/
│   ├── matching_results.tsv        # Scored leaderboard file
│   └── candidate_pairs.tsv         # Blocking candidate audit
├── code/
│   └── business_entity_resolution/
│       ├── src/                    # Full python source code modules
│       ├── README.md               # End-to-end reproduction guide
│       └── requirements.txt        # Pinned dependencies
└── Documentation_template.md       # Filled methodology writeup
```

### Prohibited Content in ZIP:
- Raw dataset files (`*.tsv`, `dataset/`)
- Temporary cache files (`__pycache__`, `.pytest_cache`, `.venv/`)
- Git history (`.git/`)
- Large intermediate files, data dumps, or parquet caches
- Credentials, private keys (`.pem`), or secrets

## 4. Hardware and Model Constraints

1. **Model Parameter Limit:** Up to 8 Billion parameters (EXP-003 LightGBM model is < 5MB).
2. **License Requirement:** Open-source permissive license (MIT / Apache 2.0). LightGBM and our custom codebase satisfy MIT.
3. **Execution Environment:** Must be runnable with standard CPU/memory constraints (peak RAM < 2.5 GB via country chunking).
4. **External Data:** Zero external lookups, geocoding APIs, or web scraping (strictly prohibited).

---

## 5. Offline Validation vs. Leaderboard Metric

- **Evaluation Metric:** Macro-average $F_{0.5}$ over all Source-1 entities:
  $$F_{0.5} = \frac{1.25 \times \text{Precision} \times \text{Recall}}{0.25 \times \text{Precision} + \text{Recall}}$$
- **Singletons Scoring:** S1 with no true matches gets $1.0$ if predicted empty, $0.0$ if any match is predicted.
- **EXP-003 Offline Benchmark:**
  - Overall Macro $F_{0.5}$: **0.6881** (Precision: 0.8448, Recall: 0.6125)
  - US Macro $F_{0.5}$: 0.6989
  - India Macro $F_{0.5}$: 0.6720
- **Official Test Set:** Unlabeled test set containing US, India, and an unseen country (France). Leaderboard score will be computed upon submission evaluation.
